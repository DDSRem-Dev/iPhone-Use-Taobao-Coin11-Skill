# 实测任务流程

按当前任务要求选用小节。2026-10-19 实测值只用于辨认，不是固定配置；流程中的15秒、5秒和奖励金额均以本次页面为准。所有坐标例子基于当时 **638×1404** 镜像截图；窗口变化后重新校准。名称不同但要求、落地页结构相同可复用；结构变化时重新分类。

## 商品浏览：好物随心逛／好物沉浸看

显示「浏览15秒 +400」，次数上限曾为 5 或 10。

1. 点击当前任务的「去完成」，等橙色商品列表真实加载，确认顶部有「浏览15秒可领400」。
2. 识别一个已加载的商品标题并点击。**此类已验证网格需要进入商品详情**，仅留在网格等15秒的测试没有完成。若另一落地页已开始倒计时或显示完成，就按其提示，无需额外打开商品。
3. 完整执行已校准的免截图序列：进入详情后按当前时长加小幅余量停留，点击详情返回，回到列表才观察。15秒任务实测17秒成功；若显示30秒，不能仍等17秒。详情没有可见倒计时也不要反复截图寻找。
4. 列表出现「完成！400能量已到账」或「已得400」即有明确成功证据。忽略「下单再得2000最高」。
5. 从列表再返回活动任务面板，核对到账与新任务布局。

本次成功序列（示例中的商品标题、返回位置均已在该窗口校准；不可直接套用其他布局）：

```javascript
await phone.click([163,579]); // 已加载列表上的商品标题
// 此处结束 UI 调用，不观察详情。
```

接着调用实际可用的等待工具，例如对15秒任务调用 `clock.sleep({duration_ms:17000})`（这是独立工具调用，不是在 `cua_repl` 中调用未定义的 `clock` 对象）。若等待工具因新消息提前结束，按实际已等时长补足；用户要求停止时立即遵从。手机切后台或连接中断时不假定停留仍有效。最后：

```javascript
await phone.click([50,200]); // 已校准的详情返回
await phone.getAXStateAndScreenshot(); // 现在已退出详情，核验完成提示
```

### 搜同款弹层恢复

详情观察后，底部可能出现「搜同款」。本次 X 为约 `[582,735]`，详情返回约 `[50,200]`。从实际画面确认坐标后连续操作：

```javascript
await phone.click([582,735]);
await phone.click([50,200]);
await phone.getAXStateAndScreenshot();
```

两次点击之间不调用 `getAXState()`、`getScreenshot()` 或组合观察。先点 X 再截图会使弹层再次出现；这是曾经反复无法返回的原因。若返回后仍在详情，不继续重复观察，检查是否有不同弹层或请用户帮助退出。

### 「看看#…／抢购超低价…」变体

任务行曾动态显示「看看#上衣」「看看#抽纸」「看看#连衣裙」「抢购超低价家用抽纸」等，并保留相似浏览要求。未逐个实测，先看落地页是否仍是有能量横幅的商品列表，再选用同类流程。不要仅凭行位置继承上一个任务的名字和计数。

## 搜一搜你心仪的宝贝

显示「浏览15秒 +400」。

1. 任务进入「搜索有福利」，提示「搜索后浏览立得奖励」。
2. 可选择当前「搜索发现」推荐词，无需输入私人搜索内容。推荐内容可能更新；实测点击时看到的词与最终查询词不同，应以结果页搜索栏为准。
3. 在带能量提示、尚未计时的已验证结果网格打开一个商品，执行上面的免截图停留与返回序列，时长以当前要求为准。
4. 核验「完成！400能量已到账」，从结果页返回活动。本次结果页一次返回就回任务列表，未要求再退出搜索入口页。

不要把商品结果页中的搜索或购买按钮当成活动奖励领取。

## 拍立淘逛感兴趣的宝贝

显示「浏览5秒 +400」。实测打开的是已有内容的图片搜索结果页，**未使用相机、选择照片或上传文件**。

等结果加载并满足5秒，观察右侧悬浮任务条「任务已完成，已得400」；右上角 X 可直接关闭回任务列表。本次无需进入商品。

如果另一版本打开相机、相册或请求权限，当前流程不再成立；确认具体需求和授权后处理，不自动上传私人图片。

## 淘金币省钱等级考试

显示「去答题最高得1000」。进入「淘金币答题／每日答题赢能量1000最高」，读题、选择答案、点「我选好了」，检查答题反馈及领取状态。

实测题目：**2026年双11活动中，赛车组队满员是多少人？** 选项为 A5、B4、C3。用户同意尝试后选5，反馈正确答案为5人，获得1000；底部「已成功领取奖励 回到主页」返回任务列表。

按题目与答案内容匹配，不能固定选A。**该次尝试恰好答对，未验证答错也获奖励**。用户同意猜答时可以尝试，不把猜测写成已知答案。

动画中经常先显示上一个支付宝小程序的快照，再切到新目标。看到旧标题时不要误认跳转失败，也不要点击旧页面的按钮。无需为「点击去逛」完成目标小程序的玩法。

这些是当时环境的结果，不是应用黑名单。若当前页面有明确的「已安装，打开」入口，可按用户的任务请求尝试打开；待真正目标页加载后执行其要求并返回核验。如果仍回下载页或要求安装、注册等额外操作，标记受阻，不循环跳转。未进入真实目标页，不能把停留在下载页当作完成浏览。

## 添加桌面小组件并回访（手动保留）

任务显示「成功回访后得1500」。已查看完整四步攻略；**用户选择跳过，未添加、未验证能量**。

官方页内引导：

1. 长按手机桌面空白处，点击左上角「+」（系统版本不同可能是编辑→添加小组件）。
2. 在组件搜索浮层搜索「淘宝」并选择。
3. 找到「淘金币」小组件，点「添加小组件」。
4. 放置完成后点击该小组件回访，再到活动核验1500能量及任务状态。

攻略最后的「去桌面添加」只是导航，翻完攻略不能当作任务完成。默认提供手动步骤；用户愿意手动完成时请其按引导操作，再回来核验。若当前主屏已有组件，可直接测试点击回访；需要新增或调整组件时依当前授权处理。本次用户的跳过选择属于探索历史，不是未来运行的永久限制或授权。

## 累计任务奖励

在任务面板顶部查看当前进度和奖励卡。实测：5次1000、20次2000、50次4000及车饰（页面标注最高，以当前值为准）。5次、20次已点击「立即领取」并看到获得能量提示；50次未达成。

点击后卡片和能量数字可能延后更新。收到奖励提示后等待后续刷新确认「已领取」，不因按钮短暂保留就重复领取。
