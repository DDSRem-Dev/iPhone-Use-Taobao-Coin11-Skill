# 淘宝双11赚能量

使用 `mcp__cua_repl.js` 操作 Mac「iPhone 镜像」，完成当前活动中可执行的能量任务并核验到账。依据 2026-10-19 的实机探索；任务名称、额度、次数和落地页会变，以当前页面为准。

## 开始

1. 首次使用先读 [镜像连接与工具注意事项](references/iphone-mirroring.md)，按工具返回的文档初始化。连接失败时按该参考恢复，不要反复调用同一个失败接口。
2. 确认手机已连接、淘宝已登录，位于「淘金币双11狂享20亿」。从活动内「赚能量」打开「做任务赚能量」。尚未在活动内时，先按当前画面可辨认的「淘金币／活动」入口导航；固定首页路径未实测，找不到明确入口再请用户打开活动，不猜深链或坐标。
3. 读取当前能量、累计任务数、可领取的累计奖励，以及各任务的「名称／要求／计数／奖励／按钮」。后续每次返回都重新识别；列表会重排、改名、改变次数上限并替换已完成任务。
4. 按下面的分类选择流程，首次执行该类任务时读取 [实测任务流程](references/task-flows.md) 对应小节。同类且布局一致时复用已成功的方法，无需重读全部参考。

## 分类与效率

按**当前要求和实际落地页**分类；任务名和奖励金额只帮助识别。新名字可以复用相同布局的流程，老名字遇到新布局必须重新判断。

| 当前要求／落地页 | 操作策略 |
| --- | --- |
| 点击去逛／跳转得 | 确认目标页加载后返回核验；不额外等17秒或参与目标玩法 |
| 浏览N秒，已有任务倒计时／完成浮标 | 按实际剩余时间浏览，已完成就返回；不为了套用商品流程再点商品 |
| 浏览N秒，已验证的橙色商品列表／搜索结果 | 打开商品，执行免截图停留序列 |
| 完成任务／答题／滑动浏览／回访 | 读现场条件，执行对应步骤，不能用只打开页面代替 |
| 下载引导／登录或权限阻断／未知交互 | 检查是否有已安装应用的正常打开路径；否则记为受阻或需人工，先做其他任务 |

优先领取已达成的累计奖励。其余任务按**预计能量 ÷ 完整耗时**选择，计入加载、跳转、返回和失败重试成本；同等收益时优先已验证且不切换应用的路线。临近累计奖励门槛时优先容易完成的任务次数。用户指定目标、顺序、预算时优先遵从，不为精确估算收益率增加观察。

每个决策点通常用一次 `getAXStateAndScreenshot()` 同时更新状态并看图，避免无变化的 AX 读取后又截图。加载中或待到账时才追加有目的的观察。已知弹层关闭和返回可连续执行，未知页面先观察；不跨越未知页面批量盲点。活动任务列表是可靠的重新定位点；「下个任务」快捷入口未验证，先保留返回列表路线。需要滚动时，若运行环境提供 `ScreenScroll` 轨迹接口，按 [镜像连接与工具注意事项](references/iphone-mirroring.md) 使用带边界的随机扰动和三次贝塞尔轨迹；没有该接口时使用兼容的 `phone.scroll` 回退。

## 商品详情页的关键约束

**商品详情页的观察可能触发淘宝截图检测，弹出「搜同款」面板。`getAXState()` 也可能产生同样副作用。**

- 已验证的「好物随心逛／好物沉浸看」橙色商品列表任务，需要进入商品才获得浏览奖励；仅在列表等待的测试未获奖励。其他落地页若已显示计时或完成提示，按该页提示处理，不强制进入商品。
- 在已加载的列表识别商品标题，然后执行完整的确定性序列：**进入商品 → 按当前要求停留 → 返回列表 → 观察结果**。从进入目标内容起计时，使用页面规定的时长并留小幅余量；15秒任务实测17秒成功，不把17秒用于所有任务。详情停留期间不调用任何状态读取或截图接口。
- 使用当前窗口中已校准的详情返回位置。尚无可靠位置时可做一次观察校准，并按下面的弹层恢复方法退出；不要盲套历史坐标。
- 已弹出「搜同款」时，**连续点击弹层 X 和商品返回，中间不观察**，退出详情后再读取状态。`点 X → 截图确认 → 点返回` 会重新触发弹层并循环。
- 除这个完整的确定性序列外，按工具要求在操作后刷新状态再决定下一步。示例和坐标适用条件见流程参考。

## 每轮执行与验收

维护简短运行记录：`任务名+要求/落地页类型 | 前计数/能量 | 尝试次数 | 成功证据 | 已到账/待刷新/受阻`。坐标只对应最新画面，不当作任务ID；名称或上限改变也不表示必然出现新任务。列表仍在刷新或切换动画中时先取稳定画面，再选下一项。

1. 选择尚未达到上限的任务，核对当前要求是「浏览 N 秒」「点击去逛」「跳转得」还是「完成任务」。不能仅凭名称推断操作。
2. 进入后先确认实际落地页。跨应用动画可能短暂显示上一个支付宝页面；等目标标题真实出现再操作。商品详情遵从免截图序列。
3. 按该页要求执行，只领取与目标有关的能量。落地页里的下单加奖、抽奖、提现、会员开通、邀请分享不属于赚取本次浏览能量的必要步骤。
4. 使用该页返回或关闭入口回到活动。支付宝任务优先使用 iOS 状态栏左上角「◀淘宝」，它与小程序内部返回不同。
5. 查看明确的「能量已到账／已得」提示、刷新后的能量增量、累计任务数或对应任务计数。任务被替换可作辅助证据；单独点击过入口、倒计时结束或页面消失不等于到账。
6. 返回后可能先看到旧数值，随后任务与能量才刷新。若结果待更新，做一次有目的的新观察；仍不明确时把该笔保留为待核验，后续回列表再核对，不立即重做或重复记账。无法与待核验项区分的入口暂不重做；明确独立的其他任务可继续。存在多笔待刷新时只报告可确认的合计，不硬分配每笔增量。成功横幅足够确认该次奖励时，无需等所有数字同时更新才继续。
7. 累计奖励按钮显示「立即领取」时点击并核验提示或「已领取」。任务奖励与累计奖励分开记录，不把领取累计奖励算成又完成一项任务。

## 例外与停止

- 同一任务完整执行后未获奖励，先排除待刷新；找到明确可修正原因时才重试一次。否则标记受阻、继续其他任务。不同营销名称若仍导向同一受阻路线，不重置重试次数；环境、要求或用户授权有实质变化后再评估。
- 无返回入口的「惊喜好物」页面曾需用户帮助退出。一个明确的返回尝试无效后请求人工返回，并保持这笔奖励待核验。
- 快手、微博曾落到下载引导页且未获奖励；这不证明未来环境也不能完成。已有应用的明确「打开」路径可按当前任务授权继续，跳过未经请求的下载注册；不能套用支付宝的成功结论。
- 小组件任务默认提供手动步骤，已有组件时可按任务要求回访；添加或调整主屏布局须有用户明确授权。当前会话用户选择跳过就遵从，不反复询问。历史选择仅记入探索记录，不当作所有未来用户的限制。
- 购买、付款、抽奖参与、分享邀请、开通服务、新权限等不因任务广告出现而获得授权。需要时说明具体动作并遵循工具的确认或人工接管要求。不要为了赚能量点击赛车升级而消耗现有能量。
- 达到用户的能量、次数或时间目标即收尾；耗时任务开始前考虑剩余预算。未指定时完成当前可执行任务，直到达到上限或仅剩受阻/需人工任务；收尾前复核列表，包括确有隐藏内容时的滚动区域，没有新可执行任务就停止。平时优先处理可见任务，不在每次返回后重复扫描整表；一次滚动无变化就检查目标区域，不靠盲滚、反复刷新、任务改名或等待次日重置无限延长。用户要求“探索后创建 skill”时，代表性流程已覆盖即可整理交付，无需刷完所有重复次数。

结束报告实际能量变化、累计奖励、未完成原因及页面停留位置。对未验证的新任务只给现场判断方法，不承诺通用成功。实测边界与证据见 [探索记录](references/verification.md)。
